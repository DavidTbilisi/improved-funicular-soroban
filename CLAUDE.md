# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive soroban (Japanese abacus) trainer that teaches a **place-value bead system** and a layered **mnemonic number-encoding scheme** (deep-pack scenes + checksum seals, decimal and hex). Originally one ~1000-line single-file page; refactored into modular ES modules with a zero-dependency toolchain.

## Commands

- `npm test` — run the unit suite (`node --test`, no dependencies). Tests live in `test/*.test.js` and cover the DOM-free layers (domain, codec, commands, drill session, stats). Run one file with `node --test test/codec.test.js`.
- `npm run dev` — serve over `http://localhost:8139` (`python3 -m http.server`). **Required for the ESM pages**: browsers block `<script type="module">` imports over `file://`, so the app must be served, not opened as a file. The `--protocol HTTP/1.1` flag is load-bearing, not cosmetic — `http.server` defaults to HTTP/1.0, which has no keep-alive, so every one of a page's ~30 module fetches opened a fresh TCP connection and the parallel Playwright suite timed out on the heaviest pages. Don't drop it.
- `npm run test:e2e` — run the Playwright browser suite (`e2e/*.spec.js`): a page-load smoke test per page plus layout/interaction regression tests that a DOM-free unit test can't see (e.g. CSS overflow bugs). This is the one dependency in an otherwise zero-dependency toolchain — `npm install` pulls `@playwright/test`, and `npx playwright install chromium` fetches the browser binary once. The suite boots its own `npm run dev` server (`playwright.config.js`), reusing one already running on :8139 outside CI.

## Architecture

The app is split into **separate static pages** (`index.html`=Today, `explore.html`=Explore, `practice.html`, `trainer.html`, `drills.html`, `anzan.html`=Flash anzan, `yomiage.html`=Read-aloud, `exam.html`=Kyu exam, `vault.html`=Vault, `game.html`=Soroban Village, `reference.html`), each a thin markup shell that loads `styles.css` and its own entry module under `src/pages/*.js`. The board-driven pages share a live soroban via `src/boardShell.js`. Everything else is under `src/`, layered so the core is DOM-free and unit-testable:

- **`src/domain/`** — pure logic, no DOM, no globals.
  - `pegs.js` = frozen data tables only (A–Z food pegs, cube faces, audio/visual matrix pegs, hex A–F). `faces.js` = digit→face grammar (incl. `cubeFaceValues` and its inverse `digitFromFaces`, the die-cell-set→digit map behind the chord keyboard). `config.js` = abacus geometry (`INT_COLS=19`, `FRAC_COLS=4` — a 23-rod standard soroban — plus contracted place labels `1`/`1k`/`1m`/`1b`/`1t`/`1qa`/`1qi`; `MAXINT` is a **BigInt**). `rod.js` = the numeric core (`{sky,earth}` rods; `index 0 = ones/tenths`). **Whole-abacus values are `BigInt`** (`intValOf`/`intValue()`/`scaledValue()`/`parseDecimal().intVal`): 19 integer digits overflow JS's exact-integer range, so the scaled-integer representation in `abacusStore.js` carries in BigInt — changing the rod count needs this, since the pre-existing `Number`-based core sat exactly at the ~15-digit ceiling. `number.js` = parse/display/`decodeChips`. `soroban.js` = the complement rule engine (`classifyAdd`/`classifySub` → direct / small-friend / big-friend move + carry/borrow) behind keyboard arithmetic. `movePlan.js` = flattens any ±digit into its full single-key chain (`planAdd(6,7)` → `+10 −5 +2`), narrating nested (compound) trades — the source for coach messages, tutorial hints, and the compound-trade figure. `chisanbop.js` = the ± friend rules as **two-hand finger arithmetic** — a hand IS a rod (thumb = the 5-bead, four fingers = the earth beads), so `handOf`/`handsOf` map a digit/number 0–99 onto hands and `chisanbopAdd`/`chisanbopSub` re-skin `planAdd`/`planSub`'s flattened steps as finger presses (±5 = thumb, ±10 = carry to the other hand): the away-from-the-abacus teaching rung, driven off the same complement engine so it can't drift from the board (its plate is `figChisanbop`, a drills-page teaching figure).
  - `codec/` = the deep-pack encoder. `cell.js` (matrixCell/hexCell/packAction **factories**), `scene.js` (scene chunking + `sceneStory` narration), `codec.js` (**Strategy**: `DecimalCodec`/`HexCodec` behind `codecForRadix`; seals live here).
- **`src/state/`** — `observable.js` (**Observer** base), `abacusStore.js` (the single source of truth for bead positions; an Observable — mutating it notifies views), `commands.js` (**Command** pattern: `SetValue`/`StepInt`/`ToggleSky`/`ClickEarth` + `CommandBus` with undo via store snapshots).
- **`src/drill/`** — `decks.js` (17 decks as **Strategy** objects, each `gen(rng)`; the finger times-table decks also declare a finite fact space via `facts` + `genFact(fact, rng)`, and `percentOf` drills the soroban percentage routine — P% of N = N×P then a two-rod ÷100 place shift), `drillMode.js` (Typed/Reveal strategies), `drillSession.js` (DOM-free Observable state machine; timing via injected clock, items via injected `rng`, persistence via injected stats service; fact decks are dealt from a shuffled **bag** — full coverage per round, misses re-dealt two items later, lifetime-weak facts dealt twice — with per-fact tallies riding in the session counters), `statsStore.js` (**Adapter/Repository**: `StatsStore` port with `LocalStorage`/`Memory` adapters + `DrillStatsService`, which also merges per-fact tallies into lifetime aggregates behind `facts(deckId)`), `forecast.js` (pure `automaticityForecast` over a deck's saved sessions — the drill-side sibling of `prognosis.js`, one line of "≈ N more sessions to automatic"), `rng.js` (`MathRng`/`SequenceRng` — the seam that makes decks deterministic in tests).
- **`src/tutorial/`** — the leveled bead-arithmetic ladder (guided practice). `levels.js` (ordered **Strategy** levels: read → direct → small/big friend ± → multi-digit, each `gen(rng)` → a problem with `startScaled`/`targetScaled`, reusing `classifyAdd`/`classifySub`), `tutorialSession.js` (DOM-free Observable state machine that drives the **shared** `AbacusStore` and detects a solve by comparing `scaledValue()` to the target — the keyboard's move-legality rejection means a correct final value proves correct technique), `progressStore.js` (**Adapter/Repository** for streak-gated unlocks, `LocalStorage`/`Memory` like `statsStore`), `solveLog.js` (per-level/mode solve records `{t, ms, clean, support}` + best clean streak, capped at 40 — feeds the pace-trend figures; `support` is the mnemonic-mental fade level the solve was landed at, injected into `tutorialSession` as `support: () => level` and the seam the prognosis reads), `prognosis.js` (**pure forecast** `prognose(solves, {floorMs, support})` → "how much more soroban practice until I can work mentally": scores automaticity over the recent same-support solves into a readiness 0..1, fits its per-solve slope, and rolls the gap-to-ready across the remaining Beads→Percept→Mental stages into an ETA in solves and minutes — refusing an ETA when readiness isn't climbing; drives Fig. 3 + the live one-liner on the practice page), `faultLog.js` (rejected moves aggregated by the complement pair their trade needed — counts, not rates, since the engine can't see correct trades), `rodTrainerSession.js` (the mult/div rod-placement walkthrough; since the practice bridge it also times and judges each solve — clean = no fault, no "Do this step", under the mode's `timeFloorMs` — with per-mode streaks persisted via `SolveLog`; modes are never locked).
- **`src/anzan/`** — **flash anzan**, the discipline the mnemonic-mental track exists to reach: numbers appear one at a time and are erased, so there is no board to read back (all DOM-free, all unit-tested). `levels.js` = the frozen rung ladder (9 rungs over terms × digits) plus `SPEEDS`, `speedStep`, and `genRound` — every term has EXACTLY the rung's digit width, the classic rule, because the width IS the difficulty and a narrow term would be a free one. Rungs are **never locked** (the rod trainer's rule): difficulty here is three independent axes — how many, how wide, how fast — and only the first two are laddered, with speed left as a live control. `anzanSession.js` = the schedule. It is **self-chaining**: each step books exactly ONE timeout for the next, never 2N up front, which makes stopping exact (one handle to clear, so an abandoned round can't flash a stray number into the next) and makes the whole thing walkable tick-by-tick against a fake timer in `test/anzanSession.test.js` — the only way to prove a flash trainer without a browser. Each number is lit for `LIT_SHARE` of the interval and blank for the rest; **the blank is load-bearing**, not styling, since without it two equal consecutive terms read as one long flash and the learner silently adds one term fewer than was shown. The pace is **pinned per round** (`roundMs_`), so a speed click mid-flash cannot rescale a round already being read or log a pace that was never shown. `bridge.js` = the **prognosis → anzan join**: `LEVEL_RUNG` maps each practice level to the rung whose shape matches, `pickRung` chooses (first uncarried rung at or above that floor, else push the pace on the top one), and `suggestRung` wraps it in the earned-it gate (`readyForAnzan`: at Mental, or at Percept with a ready+enoughData forecast). It lives here rather than in `src/tutorial/` on purpose — `prognosis.js` is pure and dependency-free and stays that way; knowing which rung suits which level is anzan's business. The gate and the choice are **split** so the Today plan can apply a looser gate (once you're doing anzan you keep being offered it) while still agreeing with the practice page about WHICH rung — one source of truth, asserted in `test/todayPlan.test.js`. The **reverse** direction lives here too: `RUNG_LEVELS` (LEVEL_RUNG inverted, so the two can't drift), `isStalling`, and `diagnoseRung` — a stalling rung → the board level to go drill. Its wording is constrained by an honesty rule worth preserving: the fault log records rejected moves on a BOARD, and anzan has no board, so **a miss here produces no fault entry and the log can never say what caused one**. What it may claim is the weaker, true sentence — this rung leans on a family of trades, and your board record already shows which pair in that family you fumble. A test asserts the message never asserts causation, and the no-evidence and wrong-family cases are reported as themselves rather than collapsed together. `anzanLog.js` = an `AnzanLog` on the `ProgressStore` port, key **`npv-anzan`** — deliberately NOT a `SolveLog`, because SolveLog compares a solve's *duration* against a floor whereas anzan's pace is imposed: what a record must carry is the INTERVAL it was answered at, and `fastest` (the fastest pace ever carried to the rung's floor unbroken) is the real score. One lucky round at 200 ms is not a personal best.
- **`src/exam/`** — the **kyu exam**: a timed paper in three sections, and the only yardstick in the app it did not invent (all DOM-free, all unit-tested). `grades.js` = the frozen 10級→1級 ladder — per-grade sections (見取算 column / 掛算 / 割算) with term counts, digit widths, question counts and a per-section clock, plus `PASS_MARK` (70) and `SECTION_POINTS` (100). The pass rule is **per section, never averaged**: a mean would let a perfect column carry a failed division, which is exactly the operator a grade exists to exclude. Each grade also names the guided-practice level it leans on (`needs`, a plain string — the same arrangement as anzan's `LEVEL_RUNG`, read by the Today plan which has both ladders in front of it). The ladder is *modelled on* the 珠算検定 grades and **certifies nothing**; the papers are shorter and division is exact, and the page says so in those words. `paper.js` = the generators + marking. Mitori-zan carries the paper-setter's rules and they are load-bearing: every term is EXACTLY the section's digit width, the first term is never negative, minus terms are capped near a third — and **a minus term may never take the running total below zero**, because the board holds the running total and there is nothing left of the top rod to borrow from. `examSession.js` = the state machine, and the two things that make it an exam rather than another drill live here: it **does not mark as you go** (every other trainer answers immediately, which is what practice is for; an exam measures what you can do without it), and the **section clock is a wall** — time saved in one section does not carry, an expired section closes with its remaining questions unattempted, and an answer submitted after the bell is not taken (expiry is checked *before* recording). Nothing is scheduled here: the page ticks it, so a whole paper is walkable against a fake clock. `examLog.js` = attempts on the `ProgressStore` port, key **`npv-exam`** — attempts, not a grade list, because "passed" is derivable from them and a stored highest-grade could disagree with the record that produced it; the paper itself is never kept (the questions were random, and a hundred numbers per attempt would be the biggest thing in the save file within a week). The exam page mounts the **full board shell**: the board IS the answer sheet (`store.intValue()` is what gets handed in), which is also what keeps the home-row keyboard live, since nothing on the page holds focus.
- **`src/yomiage/`** — **読上算, read-aloud dictation**: the numbers are SPOKEN and never shown (all DOM-free, all unit-tested). It is a third modality rather than a harder anzan — practice reaches the rods through the eyes and flash anzan does the same faster, while this one never puts a numeral on screen, so the ear has to reach the rods with nothing in between. It is also the one exercise where the BOARD does the remembering, which is why it is offered early: the column can be ten terms long without taxing memory at all. `words.js` = the call — English number→words plus `scriptFor` (open → each term → "How much?") and `estimateMs`. The **whole number** is spoken ("three hundred twenty-five", never "three two five"): reading digit by digit would hand over the rods already separated, which is precisely the work being trained. The sign is the CALLER's ("plus …" / "minus …"), never the number's. `levels.js` = a 6-rung ladder over terms × digits × minus, plus `GAPS`/`gapStep`; **the column is the exam's column** — `genRound` calls `genMitori` from `src/exam/paper.js`, so the paper-setter's rules (exact width, non-negative running total) hold here and cannot drift. `yomiageSession.js` = the schedule, and its one structural difference from `anzanSession` is that it is **driven by the voice, not by a clock**: a spoken number takes as long as it takes, so each step speaks, waits for the utterance to report done, and only then starts the gap. The `voice` port's whole contract is that `speak(text, done)` calls `done` exactly once; a generation token discards a `done` from a round that has since been stopped. The **gap is the difficulty** (how long you have to hear a number, set it, and be ready for the next) and is pinned per round like anzan's pace. There is no replay, deliberately. The log is an **`AnzanLog` on key `npv-yomiage`** rather than a new class: the record a dictation round needs is the anzan one exactly — the interval it was answered at, and `fastest` = the fastest pace ever carried to the rung's floor unbroken.
- **`src/vault/`** — **the codec's practice loop**, and the only store in the app that holds CONTENT rather than performance records (all DOM-free, all unit-tested). Everything else on the codec side teaches the encoding's *alphabet* on randomly generated items discarded after one rep; nothing ever asked the learner to hold ONE number and give it back a week later, which is the only thing the encoding exists for. `entry.js` = validation (a stray letter is an **error**, never silently dropped — dropping it would store a different number than the one given), `lociFor` (which goes through the codec's `encode`, NOT `prepare`: prepare builds its string from a board value, so it caps at the rod count and loses leading zeros through BigInt), and the **two storage modes**. `'full'` keeps the digits; **`'sealed'` does not** — only the length and the per-locus seals — so the app cannot show an answer it does not have. Sealed exists because this is unencrypted localStorage that also travels in the export file, and a memory trainer invites exactly the numbers you should not leave in plain text; the seal is a **checksum, not a hash**, catching a wrong locus ~8 times in 9 (14 in 15 in hex), which the UI says in those words. `verify.js` = the codec's missing **return direction**: not a story parser (the learner types digits) but a per-LOCUS check that uses the seal to say *which* locus broke without saying what it should have been — the `erasure` drill's idea, applied to a real stored number. `schedule.js` = the app's first genuinely **time-based** scheduling: `STALE_DAYS` is a flat flag and `dueFacts` is a mastery threshold, neither of which models forgetting, and a stored number decays with time rather than with practice count. Deliberately not SM-2 (its constants are folklore and its five-point grade scale has nothing to grade here — the seals either check out or they do not): 1 day, 3 days, then × an ease that drifts up, capped at a year, with a lapse collapsing to one day and costing more ease than a success gains. `vaultStore.js` = `Vault` on the `ProgressStore` port, key **`npv-vault`**, whose `_fix()` **never fabricates a `code`** — a healed entry must not appear to hold digits it does not have, so a 'full' entry whose code did not survive is *downgraded to sealed* rather than left promising a reveal.
- **`src/game/`** — the Soroban Village resource game's DOM-free core (all unit-tested). `buildings.js` (frozen building table + 9×6 grid constants), `economy.js` (pure functions over the plain village save blob: place/afford/yields/`advanceDay` — **one village day passes per solved contract**, so the sim has no wall-clock), `challenges.js` (contract tiers as **Strategy** `gen(rng)` objects reusing `classifyAdd`/`planAdd` for difficulty, plus the `payout` formula: base + clean bonus + speed bonus + streak bonus (⌈base/20⌉ sp per clean solve already banked, at most 10 count), × shrine blessing; the baseSp ladder is tuned so sp per *second* rises with tier), `saveStore.js` (`GameSave` over the `ProgressStore` port, key `npv-game-save`, with a `_fix()` heal/migration on load), `gameSession.js` (Observable state machine copying `tutorialSession`'s seed-disarmed/watch-the-store solve detection; earn and upgrade contracts; maintains `stats.streak`/`bestStreak`), `goals.js` (a fixed milestone ladder derived **purely** from the village blob — nothing stored; feeds the HUD's "next goal" chip and the help overlay's checklist), `advisor.js` (`nextHint`: a prioritized rule ladder that turns the village into one concrete "do this next" line for the idle strip; past the goal ladder it suggests lighting a festival when the feast is on hand, else the cheapest upgrade, forever). Payout and festival constants are **tuned against `design/hardness.flow`** — a flowloom stock-and-flow model of this economy (`design/hardness.md` has the findings and run commands); re-run it before retuning them. The **festival** is the standing resource sink (`FESTIVAL_*` + `festivalCost()` in `economy.js`): `lightFestival()` burns a feast priced at `FESTIVAL_YIELD_DAYS` (10) days of village production per resource — never less than 150 food + 50 wood + 100 coin — for +50% on payouts over the next 10 solves (`village.festival` days, burned by `advanceDay`, stacking additively with the shrine blessing). **Levels are endless** — no MAX_LEVEL: yields scale ×level and `upgradeCost` grows linearly (L1→2 and 2→3 keep the pre-endless values), `FOUNDING_LEVEL = 3` only marks the shrine's one-time founding milestone, and `RES_EMOJI` lives in `buildings.js` as shared frozen data. The game page itself is a **one-screen cockpit**: `game.html` fills `100dvh` and never scrolls — the adopted live board is scaled to fit its box by `fitBoard` in `src/pages/game.js` (a pure CSS transform; the board's bead geometry is fixed px). The board hides while idle (`display: none` off `.ck-focused`; `fitBoard` skips zero-sized calls) — taking a contract enters **focus mode**: `body.ck-focused` re-lays the same strip+board nodes out as a popup over the dimmed village (no DOM moves), and the popup lingers ~1.6s after a solve so chained contracts stay focused.
- **`src/review/`** — **retention**: how much of a skill is still there, and when it is worth a rep (DOM-free, unit-tested, and it **stores nothing**). The vault schedules memorised content; until this, nothing scheduled the SKILLS — `plan.js` had a flat `STALE_DAYS = 3` that called a deck "cold" whether it had been drilled once or forty times across a fortnight, and `dueFacts` is a mastery threshold that says nothing about time. `decay.js` = the model, and it is a choice rather than a law: `R(d) = 2^(−d/H)` with `H = HL0 · GROWTH^(s−1)`. Two decisions carry it — **strength is counted in practice DAYS, not reps** (forty solves in one sitting is one day of learning; counting reps would let a cram claim a year-long half-life), and **growth is scaled by how cleanly those days went**, so a fumbled track keeps coming back. `REVIEW_AT = 0.7`, not the flashcard world's 0.9: these are automaticity skills, and a rep at 95% is mostly wasted while one at 40% is re-learning. `skills.js` = every practised track flattened into ONE list with a forecast each — retention is the only number that means the same thing on a tutorial level, a drill deck and a paced rung, which is what lets the plan rank them against each other at all; the per-track `QUALITY` map is the only judgement left and it is stated once. The **vault and the exam are deliberately absent** (the vault has a real scheduler over content and would only produce a second answer; a passed grade does not decay into an unpassed one). Everything is derived from logs the app already keeps, so there is no new key, no migration, and no second source of truth that can disagree with the practice it came from.
- **`src/today/`** — the **day axis and the cross-app profile** behind `index.html` (all DOM-free, all unit-tested). Nothing else in the app has a calendar-day concept: every other "streak" (the tutorial unlock streak, `gameSession.stats.streak`) counts consecutive *solves*. `dayKey.js` = day arithmetic + `streakOf` — **day keys are UTC**, matching every stamp the app already writes (`new Date().toISOString().slice(0,16)`, whose local offset is unrecoverable); its load-bearing rule is that a run ending **yesterday** is still alive, just unfed, which is the state the home page exists to act on. `harvest.js` = every timestamp in the raw log blobs → day keys (the backfill source; note `npv-game-save` and `npv-fault-log` carry **no** wall-clock stamp, so village days only ever reach the streak through a live `mark()`). `dayLog.js` = `DayLog` on the `ProgressStore` port, key **`npv-days`** — it has its own key rather than deriving days from the logs because those are capped (20 sessions/deck, 40 solves/level), so a heavy single-deck user would evict their own history and watch a real 30-day streak render as 7; `seedFrom(harvestDays(...))` backfills once, the `AchievementTracker.seed` pattern. `profile.js` = `buildProfile` — one derived snapshot over all the keys (practice, drills, trainer, **anzan**, **read-aloud**, **exam**, village), carrying `activeDays` (distinct practice days, the retention model's input) beside every rep count, **reusing** `automaticityForecast`, `prognose`, `fumbleRows`, `villageRank`, `nextGoal`, `nextHint` rather than recomputing any of them; takes constructed services, never storage, and only ever reads. `plan.js` = `todaysPlan` — `advisor.js`'s prioritized-ladder shape one level up, turning the profile into ~3 tasks with a reason, a minute estimate and a deep link (a **due vault number** outranks everything including the first-run rungs — it is the only work in the app with a deadline, and skills wait where memories decay; the **kyu paper** is a checkpoint, so it sits BELOW the rung the ladder is on and the deck that is due — on a day with practice owing, the practice wins; the **anzan** rung is gated on the mnemonic-mental track having started — offering it at Beads is offering the exam before the course — while **read-aloud** is gated only on the carry being cleared and needs no mental stage at all, since the board does the remembering); a **page may appear at most once** (so the plan interleaves instead of stacking three drills) and **at least one task is always emitted** even if it busts the budget. A rule may return a **ranked array** rather than one task and the planner takes the first that fits — the retention rungs need that, since their best candidate may sit on a page an earlier rung already claimed, and yielding nothing there would drop the schedule instead of falling to the next-most-faded thing. Rung 7 (`fading`) is where `src/review/` lands: the most decayed track that has fallen through the review mark, ranked across ALL of them, with `keep-warm` as the strictly-nothing-is-due fallback using the same ordering. `deepLink.js` = the `?level=` / `?deck=` / `?mode=` / `?grade=` contract (yomiage shares `?level=`), held on both sides of the wire so writer and readers can't drift (round-tripped in `test/todayPlan.test.js`). `checklist.js` = today's ticks, key `npv-today`, self-wiping on a new day. `transfer.js` = export/import of every key as one versioned JSON blob; validation is deliberately **shallow** because each store already heals what it loads (`GameSave._fix`, `TutorialProgress._data`), and import **never clears a key the file omits**.
- **`src/view/`** — one class per panel (`soroban`, `readout`, `deepPack`, `reference`, `drill`, `tutorial`, `today`). `voiceService.js` sits beside `soundService.js` as the other browser-audio concern: it wraps `speechSynthesis` for the read-aloud caller, and its entire job is guaranteeing `done` fires **exactly once** — browser speech drops `onend` when the tab blurs, never fires it with no voice installed, and fires it again on `cancel()` — so every utterance races its own end event against an estimated duration, and "no voice installed" degrades to a silent, captioned round rather than a frozen page. Views **observe** the store/session and emit user intent through injected callbacks; they never mutate state directly. `SorobanView` also owns the **mnemonic-mental track** (`setSupport`/`peek`): a CSS support-fade ladder on the board — Beads → Percept (only the per-rod die-face percepts — each rod's `.rod-cube` renders `cubeFaceGrid`) → Mental (imagined rods, faded by `visibility` so nothing reflows) — wired with an `M`-cycles / `P`-peeks control on the guided-practice page so the same arithmetic can be drilled blind while the solve still verifies by value. A sibling `RodRailView` renders the **focused-rod rail** (the perpetual-calendar "lift the active tab" mechanism, icons only: one food-peg emoji per rod, the focused one lifted, and a small die-face panel below for its digit), fed by the board shell's `setFocusHook` — the "which rod am I on?" anchor that survives the fade. `figures.js` is the exception to "views aren't tested": it holds the numbered textbook figures (bead-state plates, complement arcs, the live place-value log chart, the multiplication-table heatmap, progress/results charts, `figPrognosis` — the Beads→Percept→Mental readiness runway + gauge for `prognose()`, which takes an optional `onward` stop drawn dashed past Mental (a different page, not a fade stage) — `figStreak` — the weekday-aligned calendar ribbon of practised days — `figAnzan`, the paced-rung ladder on a log pace axis where faster is further right (both flash anzan and read-aloud chart through it — `what` names the rung rather than the chart being copied), `figExam`, the kyu ladder drawn hardest-at-the-top with each grade's best score against the 70 rule, `figRetention`, every practised track's remaining retention on one axis against the review rule, and `figVault`, the review schedule on a log day-axis) plus `lociHTML`, the deep-pack loci strip extracted from `DeepPackView` so the vault can render scenes for a code that has no board behind it plus `cubeFaceGrid` (a digit as a **die face** — each cube emoji in its fixed cell: taxi center, alien top, tangerine left, rose right, wave bottom; opposite faces sum to 7) as **pure SVG/HTML string builders** — no `document` — so it is unit-tested like the domain.
- **`src/pages/*.js`** — one composition root per page; with `src/boardShell.js` (the reusable live-board unit: store + soroban + readout + keyboard + sound/metronome) and `src/nav.js`, — the keyboard is the **die cross**: each hand's home cluster maps to the digit's die cells (center 1 / left 2 / top 3 / bottom 4 / right 5), right hand adds and left subtracts, the ±10 carry keeps its own `U`/`R`, and holding cells together **chords** the compound 6–9 (a ~45 ms debounce resolved by `digitFromFaces`, applied strictly like the single keys) — these are the only modules that touch `document`. Each page instantiates the graph and wires controls → Commands → store → views. `today.js` is the odd one out: it mounts **no** board (nothing is practised there, so no soroban, keyboard or audio context), reads every store at once, and owns the single `todayKey()` clock seam for the whole day axis. The seven practising pages each call `dayLog.mark()` on real work — `solved` on practice/trainer/game, `result` on anzan and read-aloud, `finished` on the exam, and **`result`** (not `stopped`) on drills, because a session the learner never stops is never saved and waiting for the stop would silently lose the day — and each reads its deep-link target from `location.search` via `targetFromSearch`.

### Data flow (Observer + Command)

User action → a page/board-shell builds a **Command** → `CommandBus.run` executes it against `AbacusStore` → store `notify()`s → subscribed **views** re-render. The drill is a parallel loop: `DrillView` forwards input to `DrillSession`, which emits events the view renders. Because the store/session/codec/decks take their dependencies by injection, all of it is tested without a browser.

## Conventions

- **Frozen tables are contracts.** The peg/face/matrix tables and the seal rules (`sealDigit` = digit-sum mod 9→9; `sealHex` = nibble-sum mod 15→F) are described as "frozen"/"registered" and reference external spec docs not in this repo (`soroban-learning-method`, `number-codec-ladder`). Changing a peg or seal rule silently breaks numbers users have already memorized — flag such changes, don't make them casually.
- **Keep the DOM out of `src/domain`, `src/state`, `src/drill`, `src/tutorial`, `src/anzan`, `src/yomiage`, `src/exam`, `src/review`, `src/vault`, `src/game`, `src/today`.** New logic belongs there (and gets a test); only `src/view/*`, `src/pages/*`, `src/boardShell.js`, and `src/nav.js` may reference `document`/`window`.
- **Phaser is vendored and quarantined.** `vendor/phaser.esm.js` is a pinned single-file build (see `vendor/README.md`; named exports only — `import * as Phaser`). It touches `window` at import time, so it may be imported **only** from `src/view/game/*` — never from `src/game/` or tests. The game page boots it with `input: { keyboard: false }` (so the board shell's document-level home-row keys keep working) and `audio: { noAudio: true }` (the app's `SoundService` owns audio).
- Emoji are load-bearing data, not decoration — keep `emoji`/`word`/`color` in sync when editing tables.
